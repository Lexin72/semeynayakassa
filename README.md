# Семейная касса

Семейный учёт расходов: сайт/PWA и Android-приложение с общей базой Supabase.
Сайт публикуется вместе с каталогом `vendor`, без сборки.

## Android-приложение

В каталоге `android/` находится устанавливаемое Android-приложение на Capacitor 8.
Интерфейс выполняется в Android WebView, но его HTML, JavaScript, шрифты и изображения
включены в APK и не загружаются с GitHub Pages. Данные и очередь отправки сохраняются
атомарно в SQLite в закрытом каталоге приложения; браузерный кэш для этого не используется.

Все участники подключаются к той же семейной базе. Сохраняются просмотр общих трат,
фильтр по участнику, аналитика, категории, бюджет и профили. Как и в исходном проекте,
выбор участника — это профиль, а не отдельный вход Supabase Auth. Android-приложение
не изменяет серверные правила доступа и не создаёт новую независимую кассу.

При первом запуске на каждом телефоне нужно подключиться к Supabase и загрузить
существующие данные. Если сервер доступен только с VPN, первое подключение и обмен
потребуют VPN. После успешной загрузки можно просматривать историю, добавлять,
изменять и удалять расходы без сети. Сохранение подтверждается только после записи
в SQLite. Общий итог на устройстве включает его ещё не отправленные расходы;
на остальных устройствах они появляются после обмена с сервером.

Синхронизация запускается после локального изменения, при возврате в приложение,
по сигналу Realtime и каждые 30 секунд, пока приложение открыто. При закрытом
приложении фонового Android-сервиса нет. Индикатор «Состояние» показывает очередь,
время последнего обмена, конфликты и позволяет вручную повторить обмен или экспортировать
резервную копию JSON (включая ещё не отправленные операции). Автоматического импорта
этой копии пока нет; она пригодна для восстановления разработчиком.

Отправка повторно проверяет запись по постоянному ID, поэтому потеря ответа после
успешной записи не создаёт дубликат. Изменения и удаления расходов используют
проверку предыдущих значений на сервере. Если одну трату изменили на двух устройствах,
очередь останавливается: в «Состоянии» нужно выбрать версию телефона или сервера.
Неотправленные изменения не выбрасываются при ошибках сети или отказе сервера.
Для больших фотографий профиля проверка выполняется до записи, без атомарного
сравнения фотографии в URL; одновременное изменение фотографии может завершиться
последней записью. Остальные устройства, работающие со старым сайтом, не имеют
проверки конфликтов при своей записи, поэтому для неё лучше обновить все устройства.

Текущий механизм при обмене читает полную историю порциями по 1000 записей. Он
рассчитан на личную семейную кассу; для очень большой базы потребуется серверная
синхронизация изменений с журналом удалений. Миграции базы в этой версии не нужны.

### Установка и сборка

Требуются Android 7+ и обновлённый Android System WebView/Chrome 100+.
Для разработки: Node.js 22+, JDK 21, Android SDK 36 (обычно из Android Studio).

```sh
npm ci
npm test
npm run sync:android
npx cap open android
```

Для тестового APK: `npm run build:apk`. Результат:
`android/app/build/outputs/apk/debug/app-debug.apk`.
Также workflow **Android APK** проверяет код, запускает браузерные тесты и собирает
APK с Android Lint. ZIP с APK находится в **Actions → Android APK → Artifacts →
semeynaya-kassa-android-test**. Для установки скачайте и распакуйте ZIP, затем откройте
APK на телефоне и разрешите установку для приложения, через которое открыли файл.

Это тестовая сборка с отладочной подписью. Для постоянных обновлений нужен отдельный
сохранённый ключ подписи release; его нельзя публиковать в репозитории. Ключ debug
на новом GitHub runner может отличаться, и Android не установит такую сборку поверх
старой. Перед удалением приложения для переустановки убедитесь, что очередь пуста,
и сохраните резервную копию. Удаление приложения или очистка его данных удаляют
локальную базу вместе с неотправленными расходами.

## Сайт: запуск и сохранённые данные

Интерфейс открывается до завершения запросов к базе. Участники, категории, бюджет
и последние 12 загруженных диапазонов трат сохраняются в браузере. При повторном
открытии эти данные показываются сразу и проверяются в фоне. Первое открытие
нового диапазона требует связи с базой. Сохранённые данные могут быть устаревшими.

Запросы к базе ограничены 12 секундами. При отсутствии связи приложение показывает
сообщение и кнопку «Повторить». Ошибка загрузки не подменяет траты нулевыми суммами.
Неуспешные изменения не показываются как сохранённые и автоматически не повторяются.
Если запрос на запись прервался, проверьте данные после восстановления связи перед
повторным добавлением: сервер мог принять запись до потери ответа.

Service worker сохраняет только файлы приложения и отдаёт их из кэша сразу,
проверяя обновления в фоне. Он не сохраняет ответы Supabase. Для офлайн-запуска
нужно хотя бы раз успешно открыть новую версию сайта и дождаться установки кэша.
При обновлении старой установленной версии откройте сайт с рабочим соединением;
после загрузки обновления закройте и снова откройте приложение.

## Доступ без VPN

Внешние CDN и скрипты Kaspersky исключены из загрузки приложения, но запросы
к Supabase по-прежнему идут напрямую. Если из вашей сети недоступен Supabase,
сохранённые данные можно просматривать, а синхронизация и запись требуют доступного
соединения. Если недоступен сам хостинг сайта, первое открытие тоже невозможно.

Чтобы обеспечить полноценную работу без VPN, сначала определите недоступный домен.
Для Supabase возможен сервер-посредник на доступном домене; для хостинга — перенос
сайта. Доступность нужно проверить из целевой сети до переноса. Эта версия не
создаёт сервер, не переносит базу и не изменяет настройки Supabase.

## Проверки

```sh
npm install
npm test
npx playwright install chromium
npm run test:browser
```

Проверки используют локальный сайт и подставные ответы API; настоящие семейные
данные не читаются и не изменяются.

Тесты Android-логики проверяют два устройства, общие и личные итоги, офлайн-запись,
перезапуск, потерянные ответы сервера, ошибки диска, конфликты, сохранение изменений
во время обмена и чтение более 1000 записей. Проверки интерфейса используют тот же
локальный клиент. Успешная сборка APK не заменяет проверку на реальном телефоне.
